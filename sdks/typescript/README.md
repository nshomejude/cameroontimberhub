# TypeScript API types (`sdks/typescript`)

Generated TypeScript type definitions for the `/api/v1` buyer JSON API,
produced from the OpenAPI 3.1 spec that `dedoc/scramble` already generates
(see `docs/api/README.md`). This is scoped exactly as the architecture
blueprint's §4 "SDKs" line describes it: a **Phase 3+ nice-to-have**, not a
full client library.

## What this is (and isn't)

- `api-types.ts` — pure TypeScript **type** definitions (`paths`,
  `components`, `operations`) generated by
  [`openapi-typescript`](https://openapi-ts.dev/). No runtime code, no HTTP
  client, no dependency for consumers — you bring your own `fetch` (or
  axios, or whatever) and get autocomplete + compile-time safety against the
  real API shape.
- **Not a full SDK.** There is deliberately no wrapper class, no
  request-builder, no retry/auth logic here. Consumers (a third-party
  integrator, or the React Native buyer app) write their own thin client and
  import the types.

`openapi-typescript` was chosen over a full codegen framework (e.g.
`openapi-generator-cli`, which requires a Java runtime) because it needs
zero runtime dependency for consumers, needs no server-side PHP changes
beyond the spec Scramble already produces, and is a single, well-maintained,
lightweight devDependency (`package.json`).

## Regenerating

Two steps — export the current spec from the running Laravel app, then
generate types from that static file:

```bash
php artisan scramble:export --path=storage/app/openapi.json
npm run sdk:generate
```

`npm run sdk:generate` runs:

```
openapi-typescript storage/app/openapi.json -o sdks/typescript/api-types.ts
```

Regenerate and commit the result whenever `/api/v1` routes, FormRequests, or
API Resources change.

## Staleness check

`npm run sdk:check-stale` regenerates the types into a temp file and diffs
them against the committed `api-types.ts`, failing loudly (non-zero exit) if
they differ. It assumes `storage/app/openapi.json` is already current — run
the `php artisan scramble:export` step above first:

```bash
php artisan scramble:export --path=storage/app/openapi.json
npm run sdk:check-stale
```

This is a real diff-check, not just a documented manual step, but it is
**not wired into the Pest suite** (`tests/Feature/Api/OpenApiDocsTest.php`)
because it needs Node/npm, not just PHP — Pest's process runs under PHP
only, so shelling out to `npx` from a Pest test would make the PHP test
suite depend on the Node toolchain being installed and would silently no-op
in any environment where `node_modules` isn't present. `check-stale.mjs`
stays a standalone Node script; `OpenApiDocsTest.php` carries a comment
pointing maintainers here. Wire `npm run sdk:check-stale` into CI as a
separate job step if/when this repo gets a CI pipeline for the JS
toolchain.

## Usage example

```ts
import type { paths } from './api-types';

type ProductListResponse =
  paths['/products']['get']['responses'][200]['content']['application/json'];

async function listProducts(): Promise<ProductListResponse> {
  const res = await fetch('https://cameroontimberhub.test/api/v1/products', {
    headers: { Accept: 'application/json' },
  });

  if (!res.ok) {
    throw new Error(`GET /products failed: ${res.status}`);
  }

  return res.json() as Promise<ProductListResponse>;
}
```

## TypeScript availability note

This repo's JS toolchain (`package.json`) does not currently include
`typescript` as a dependency — it's a Vite/Blade frontend, not a TS app. A
new `typescript` devDependency was deliberately **not** added just to run
`tsc --noEmit` against the generated file, per the same
add-nothing-you-don't-need principle as the codegen tool choice above. The
generated file's structure was instead visually confirmed to be sane
(well-formed `paths`/`components`/`operations` interfaces, correctly
mirroring the routes in `routes/api.php`). If this project later adopts
TypeScript for real (e.g. the React Native app's build, or a future admin
SPA), add a `tsc --noEmit sdks/typescript/api-types.ts` check at that point.
